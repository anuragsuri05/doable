# v0 (by Vercel) — Product Reference for Building a Clone ("doable")

> Research date: 2026-10-22. Primary source: the official v0 docs bundle (`https://v0.app/docs/llms.txt`, every page stamped `lastUpdated: 2026-10-21`), the official changelog (`https://v0.app/changelog`, Oct 2025 to Oct 19 2026), the pricing page, Vercel blog posts, and third-party reviews.
>
> Conventions:
> - **[confirmed]** means stated in official docs or changelog.
> - **[uncertain]** means third-party only, conflicting sources, or inferred.
> - **[legacy]** means it existed in earlier versions of v0 and may be gone or renamed.
> - Model names such as "GPT-6 Astra", "GPT-5.6 Sol", "Claude Opus 5" and "Gemini 4" are copied exactly from v0's own docs and changelog.

## 0. TL;DR for clone builders

v0 is a **chat-first, agentic, full-stack app builder**. The user types a prompt. An AI agent plans, asks clarifying questions, writes a Next.js, React, Tailwind and shadcn/ui codebase, and runs it in a **per-chat cloud VM (Vercel Sandbox)** with a live preview. The user iterates through chat, a visual **Design Mode**, a **Code** tab and a terminal. Shipping is one **Publish** button that deploys to Vercel. Projects that use GitHub get a branch, pull request, merge and deploy flow.

The core objects are listed below.

| Object | What it is |
|---|---|
| **Scope / workspace** | A Vercel team. Since Oct 6 2026, personal accounts are team workspaces too. Holds members, billing, credits, skills and settings. |
| **Chat** | A conversation plus a sandbox plus files plus messages. This is the main unit of work. |
| **Message** | A user or assistant turn. Assistant messages contain ordered *parts*: text, thinking, file-read, file-edit, search, bash, tool-call and agent-action. |
| **Version** | A code snapshot created when an assistant message changes code. It can be restored, diffed or forked. API v2 removed versions as a resource. |
| **Project** | A Vercel Project, meaning one app shared by many chats. It owns deployments, environment variables, domains, integrations and Git. |
| **Folder** | A plain grouping of chats (since Jan 27 2026). |
| **Skill** | A reusable instruction pack (`SKILL.md`). Sources are memory (user or team), remote (skills.sh) and project (from the repo). Design systems are skills. |
| **Instruction** | A saved reusable prompt rule that the user toggles on per chat (for example "Be Concise" or "Plan Mode"). |
| **Integration** | A Vercel Marketplace resource, MCP server, Vercel Connect connection, or native integration (Figma, Snowflake, Shopify, Stripe). |
| **Template** | A published chat that others can fork. Visibility is community or team. |
| **Deployment** | A Vercel preview or production deployment. |

The main surfaces are:
- Home with a centered composer.
- A sidebar listing chats grouped by project.
- The chat view: chat panel on the left, and a workspace panel with **Preview / Design / Code / Database** modes plus a console with Logs and Terminal.
- The header with project, branch, **Invite** and **Publish**.
- Settings pages.
- The Templates gallery.
- The Design Systems page.
- Usage & Activity.

## 1. Product overview and positioning

- **Tagline in the docs:** "v0 is an AI agent that helps anyone create real code and full-stack apps and agents." It lets you "ship features, refine designs, update copy, and create live prototypes, all with a prompt. Deploy to production immediately, or open a pull request for review." [confirmed]
- **Audiences:** founders (MVPs), product managers (prototypes, PRDs), designers (Figma or screenshot to UI), engineers (scaffolding, pair programming), data scientists (Snowflake, SQL, Python), marketers (landing pages), educators, customer support (chatbots, knowledge bases), and sales engineers (demos). [confirmed]
- **Claimed differentiators:**
  - End-to-end UI plus backend.
  - Fits the Vercel stack.
  - Supports team workflows.
  - Extensible through APIs, databases, MCP, and design systems.
  - Agent capabilities: web search, browser use and site inspection, error fixing, terminal, external tools.
  - Real-time feedback: live preview, progress indicators, screenshots.
  - Multi-modal input. [confirmed]
- **Versus competitors (official comparison pages, reviewed July 28 2026):**
  - Bolt: v0 uses Vercel hosting and per-chat Git branches with pull requests. Bolt uses `.bolt.host` and Bolt DB.
  - Replit: v0 uses Vercel deploys. Replit has Autoscale, Reserved VM and other deploy types.
  - Base44: v0 has code-controlled backends. Base44 uses a managed NoSQL backend.
  - Figma Make: v0 has real Git workflows. Figma Make only pushes one way to GitHub.

  v0 also cites SOC 2 Type 2, ISO 27001:2022, GDPR and PCI DSS through Vercel. [confirmed]
- **Users:** about 3 to 3.5M by Aug 2025 (The New Stack and others), and "4 million+" by early 2026 (SaaStr and others). [uncertain]
- **Languages:** you can prompt in any language and v0 responds in the same one. The UI added Simplified Chinese on Feb 18 2026. [confirmed]
- **Platforms:**
  - Web at v0.app.
  - **iOS app** (launched Oct 23 2025; Sign in with Apple from Nov 18 2025). The app can start and continue chats, preview, manage environment variables, connect GitHub, share, set up database integrations, and select MCP servers. Adding new MCP presets is desktop-only.
  - A **Slack bot** in beta.
  - The **v0 MCP server** and the **Platform API / SDK**. [confirmed]

## 2. Tech stack of generated apps

- **Default:** Next.js (App Router; Next.js 16 for new chats since Oct 22 2025, 16.2.0 since Mar 19 2026), React, TypeScript, **Tailwind CSS v4** (4.2.0 since Feb 2026), **shadcn/ui**, Lucide icons, and **AI SDK v6** for AI features. [confirmed]
- **Default full-stack scaffold** (since Jun 8 2026): **Neon Postgres + Drizzle ORM + Better Auth** when an app needs a database and auth. [confirmed] Older guidance said v0 connects to Supabase, Neon or Upstash "without ORMs by default". [legacy]
- **AI features:** Vercel **AI Gateway** with zero-config auth for text, structured output, embeddings, reranking, images, video, speech and transcription (Aug 28 2026). Chat UIs are built with **shadcn/ui chat primitives** and the latest AI SDK, replacing the deprecated "AI Elements" (Jul 7 2026). [confirmed]
- **Other frameworks:**
  - Vite and generic Node are detected by the sandbox.
  - Nuxt and Nuxt UI (Mar 2026).
  - Svelte can work in imports.
  - Python Services backends (Mar 2026).
  - Monorepo and Turborepo support.
  - v0 can answer questions about Svelte, Turborepo and others, but **Next.js gives the most reliable results**.

  Reviews say v0 "does not output Svelte or Vue" for new UI. [partly uncertain]
- Server Components, Server Actions and Route Handlers are used for backend logic. `NEXT_PUBLIC_` is the only prefix exposed to the client, and v0 warns about risky `NEXT_PUBLIC_` usage. [confirmed]
- **Other built-in knowledge:** i18n with `next-intl`, Vercel Flags (feature flags, Jun 2026), SVG generation skill (Jun 2026), image generation (up to 5 images per version through the API), and Mermaid ER diagrams for schemas in PRDs. [confirmed]
- **New-chat starter:** `v0-default` starter (Next.js, shadcn/ui, Tailwind). A design-system skill can override this with its own starter. [confirmed]

## 6. Chat view (editor) in detail

Layout: **chat panel** on the left (collapsible, resizable) and a **workspace panel** on the right (resizable with drag handles since Mar 4 2026). On phones the panes switch.

### 6.1 Chat header

- **Breadcrumb:** scope / project name (connected project shown at top) / chat title (auto-generated and de-duplicated; titles describe product identity).
- **Chat menu (…)**:
  - Rename.
  - **Duplicate…** (Duplicate Branch dialog for Git chats; otherwise it copies the chat and can stay linked to the same Vercel project).
  - **Transfer Chat** (to another scope; it moves the linked Vercel project when you are its Owner).
  - Favorite.
  - **Download ZIP** (native Save As; view-only members can download).
  - Archive.
  - Settings.
  - "Request access" for private team chats.
- **Project menu (…)**: mirrors the chat menu and adds **Settings** (see §9).
- **Branch button** for GitHub-backed chats (§11.2).
- **Invite** opens the centered Invite dialog (§13).
- **Publish** opens the publish popover or wizard (§12). It is disabled with a tooltip when there is nothing to publish, while v0 is responding, or when you lack permission.

### 6.2 Chat panel

- **User messages** can contain text, attachments, annotation lists and code comments.
- **Assistant messages** stream as a sequence of visible steps:
  - **Thinking** (collapsible reasoning).
  - **Plan / to-do list** (agent to-do management).
  - **Task rows / tool execution cards**: file reads, file edits (with path and lines changed), searches (web search with **citation links**), **bash** commands with output, MCP/tool calls, skill-loaded rows ("Loaded skill: X"), integration cards, and browser-use **screenshots**.
  - Final **text** summary.
  - **Work Details** footer (since Oct 31 2025): time worked, files modified, lines changed, credits used.
- **Interactive agent pauses** (also in the API as resolvable tasks):
  - **Plan review**: "exit plan mode" with approve, request changes or reject.
  - **Clarifying questions** (since Dec 17 2025, shown in-form since Jun 2026).
  - **Permission requests** for bash and MCP.
  - **Integration setup cards** (connect Supabase, Neon, Stripe and others; **Integration Wizard** runs setup scripts such as DB migrations or seeding).
  - **Environment-variable request** forms.
  - Vercel Connect authorization cards.
  - The **Connect Shopify / Connect Snowflake** cards.
- **Auto-continue**: long runs continue past timeouts. A paused-agent timeout card shows "Resuming" and then "Resumed".
- **Message actions** (confirmed set: version controls on generated messages to **view a version, view its diff, restore**; **retry with a model choice** since Mar 3 2026; upvote/downvote feedback; copy). **Edit prompt** is likely and **Fork from this version** exists in the API and UI ("fork modal" mentioned Jan 16 2026). [partly uncertain]
- **Version switching**: a searchable **version selector** in the preview (Jan 16 2026). Restoring creates a new latest version, so history stays linear. Deploy always uses the latest version. Since Feb 2026 a Git revision backs each version, and Mar 16 2026 added full-version snapshots.
- A **sound notification** plays when v0 finishes while the window is unfocused (Settings toggle, on by default).
- An **out-of-credits notice** ("You are out of credits") appears, with low-credit warnings and an auto-recharge opt-in.

### 6.3 Workspace panel: modes / tabs

The editor modes are **Preview, Design, Code, Database** (illustrated tooltips added Aug 2026), plus a **Diff** tab per message and a **Console** panel.

#### Preview
- An iframe of the dev server running inside the chat's **Vercel Sandbox VM**.
- Toolbar:
  - Back/forward/refresh.
  - **URL/path bar** for in-app navigation.
  - **Version picker**.
  - **Device/viewport toggles** (desktop, tablet, mobile) [uncertain in 2026 UI; Design Mode is unavailable on mobile viewports].
  - **Open in new tab / fullscreen**.
  - **Restart** for a stopped preview.
  - Design Mode toggle.
  - **Annotations mode**: click elements to drop numbered comments, then send them as one batch (Jun 19 2026).
- Loading states: the previous preview shows immediately while the VM boots, with a subtle progress line and a "zebra loader". "Warming up preview" is a known state.
- Errors: when the dev server fails to boot or install, a compact **error bar** under the preview links to the exact console log line. Runtime errors show a **Fix with v0** action. The Next.js dev overlay is suppressed inside the embedded preview.
- Previews support **Sign in with Vercel** inside the VM (same origin) and the favicon syncs to the browser tab.
- Preview access: the preview origin is authenticated. Share links open via the auth path.

#### Design Mode (visual editing)
- Opened with the **Design** button or tab in the preview toolbar. It is available only on the latest version, on VM-preview chats, and on chats you can edit. It is not available on mobile viewports.
- Layout: **layers viewer**, **floating toolbar** on selection, **properties / design panel**, **inspector**, **measure overlay** for spacing (Jun 2026).
- Selecting elements:
  - Hover highlights and click selects, with selection handles.
  - **Cmd/Ctrl+I** toggles Inspect vs interact.
  - **Escape** deselects.
  - **Arrow keys** navigate elements.
  - **Enter** edits.
  - **Cmd+click** quick-selects.
  - A shortcut deletes the element.
- Design panel controls:
  - **Typography**: font family (real font names), size, weight, line height, letter spacing, alignment, decoration.
  - **Color**: text color.
  - **Background**.
  - **Layout**: margin and padding on all sides.
  - **Border**: color, style, width.
  - **Appearance**: opacity, corner radius.
  - **Shadow**.
  - **Content**: inline text editing. Non-editable text is explained.
- Tailwind-aware value surfacing.
- **Instructions box**: a natural-language prompt about the selected element. An element screenshot is auto-attached.
- **Image editing with Nano Banana**: select an image and prompt a change (Oct 30 2025).
- Undo, Redo, Reset (clears pending edits on the element), and a Before/After toggle.
- Pending edits are kept until you click **Apply**. Leaving with unapplied edits shows a warning.
- **Apply** serializes the edits, instructions and screenshot into a chat message. That creates a new version, which you can diff and revert.
- Embeddable through the API: `createDesignModeBridge` from `v0/browser` and `parseDesignModeMessage`.

#### Code (Code Viewer, new lightweight version Sep 25 2026)
- **File tree** with **New file** and **New folder** buttons. Right-click offers New file, New folder, Rename, Delete (with confirmation). Inline name editing: Enter confirms, Escape cancels. Empty folders are not persisted.
- **Search icon** above the tree: filename and content search with arrow-key navigation. The older editor had **global search & replace** with include/exclude filters.
- Editor: syntax highlighting, line numbers, undo/redo. Edit access is needed. UTF-8 text up to **1 MB**. Binaries are read-only. Images preview. Markdown and SVG preview.
- **Copy file contents** and **Download file** in the file header. Large unpreviewable files show a Download action (Oct 16 2026).
- Autosync to the workspace after a typing pause. An **Unsaved Changes bar** offers **Save** (commit; Cmd/Ctrl+S) or **Discard** (restore the last commit, remove created files). Manual editing pauses while the agent works. Sending a prompt syncs pending edits.
- **Add to chat / code comments**: select code, click "Add to chat", write an optional comment, then **+**. The prompt carries the file path, lines, captured code and comment. The annotation list in the composer lets you edit (pencil) or remove. In read-only views, click or drag gutter line numbers.
- Editor history:
  - Dec 10 2025 editor: file and folder create, global search/replace, diff view, split view.
  - Jan 8 2026: inline chat in the VS Code editor.
  - Feb 2026: full **VS Code (code-server)** editor in the VM panel, activity bar at top, Geist-matched theme.
  - May 2026: autosave, Vercel Light/Dark themes.
  - Sep 2026: replaced by the lightweight Code Viewer.

## 11. GitHub and Git workflow

### 11.1 Concepts

- Branch types:
  - **Default branch**: the repo default.
  - **Base branch**: the chat starts here and pull requests target it.
  - **Working branch**: created lazily on the first code change, for example `v0/main-abc123`. Named from the chat title and kept stable after the pull request exists.
  - **Production branch**: the Vercel project setting.
- v0 **never pushes directly to main or base**.
- Every code change is **auto-committed and pushed** to the working branch. Commits are **signed/verified** (Jun 2026). Pull requests carry a "v0" label.
- Each working branch gets a **Vercel preview deployment**.
- Once connected, the repo becomes the source of truth. Deleting the repo can lose code.
- Collaboration with Cursor or Claude Code users goes through the same repo: pull and push. **Pull Changes** brings base commits in, and **auto-pull** runs when pull requests merge outside v0.

### 11.2 Branch menu (next to Publish)

- Shows the preview deployment (status and URL), branch link and diff (+/−), **Create PR / Open PR**, **CI checks** (running, passing, skipped, failing), **Pull Changes**, merge PR, and a contextual v0 action (Review Code, Fix Build, Fix CI, Fix Conflicts, Fix CI + Conflicts).
- "No active preview" appears until the first push.

### 11.3 Import from GitHub (Jan 28 2026)

1. **+ → Import from… → Import from GitHub**.
2. Paste a URL or pick an org and search repos. The **Vercel GitHub App** must have access to the repo.
3. Configure:
   - Without an existing Vercel project: **Team, Project Name, Base Branch, Root Directory** (monorepo support).
   - With an existing project: choose the team and project or create a new one. This inherits dev env vars, integrations, framework and root settings, deployments and domains.
4. **Import** creates the chat, a sandbox at the base branch, and a working branch and preview on the first change.

Re-importing creates another chat and branch, not another repo. The package manager is detected from the lockfile.

### 11.4 Other Git features

- **Duplicate Branch** creates a new chat and branch carrying the current commits.
- **Allow v0 to Act on Behalf of Members** is a workspace setting for members without GitHub on their Vercel account.
- A toggle controls v0 bot Git actions (Team and Business).
- Branch protections, required checks and reviews are respected. A blocked publish keeps the pull request open and links to it.
- v0 respects the default branch name setting when creating repos.

## 19. Platform API, SDKs, MCP server

### 19.1 Platform API v2 (beta Jun 26 2026; current)

- Base URL: `https://api.v0.dev/v2` (alias `https://v0.app/api/v2`). Auth is `Authorization: Bearer $V0_API_KEY` (keys at `/settings/keys`).
- Install with `npm i v0`. Exports include `v0`, `fetchPreview`, `v0/browser` (`createDesignModeBridge`, `parseDesignModeMessage`).
- **Chats**: create (sync, async or stream), create from **repo**, **ZIP** (by URL or data URI), **files** (inline UTF-8 or base64), or **Vercel project**. Also get, list (metadata filters), update (title, privacy, metadata), delete, duplicate, get/update/download files, **getPreview** (URL plus short-lived token), restore message, resume stream, deploy, create Vercel project, Connect setup status.
- **Messages**: send (sync, async or stream; supports `designMode` edits), list, get, **resolve task** (sync, async or stream), stop.
- **MCP servers**: CRUD (no auth, bearer, custom headers, OAuth), OAuth authorization URL. Up to 100.
- **Webhooks**: CRUD. Events: `chat.created|updated|deleted`, `message.created|updated|deleted|finished`.
- **Settings**: trusted preview hosts (get/set/append/delete; up to 100 patterns; `*.` and `**.` wildcards).
- **Usage**: summary, events, activity.
- **Create chat body**:
  - `message`, `systemPrompt`.
  - `modelConfiguration{modelId, imageGenerations}`.
  - `attachments[]`, `mcpServerIds[]`.
  - `skills[]` (max 3; `remote`, `memory` or `project`).
  - `privacy`, `title`, `metadata`.
  - `credentialAccess{sharedNpm, vercel, github}`.

  The response includes `usage{model, tokens{input, output, cacheRead, cacheWrite, total}, creditsCost{…}}`.
- **Message parts**: `text, thinking, file-read, file-edit, search, bash, tool-call, agent-action` (for example `exit_plan_mode`, `ask_user_questions`, Vercel Connect setup).
- **Resolve task types**: `plan-exit-response` (approved, request-changes or rejected, with content), `answered-questions` (questionId, selectedLabels, customText), `confirmed-permissions` (echo `suggestedPermissions`), `confirmed-steps` (integration scripts). 409 on mismatch.
- Stream events include `message.parts.chunk`, `message.usage`, `chat.title`, and others. Errors: 422 on model refusal (do not auto-retry), 500 on unexpected failures.
- **v1 to v2 changes**:
  - v0 Projects are deprecated in favor of chat `metadata` and `vercelProjectId`.
  - Versions are removed (chat equals the current state, messages equal history).
  - Explicit sync, async and stream endpoints.
  - v2 chats are VM-only and incompatible with v1 chats. Migration path: download the v1 version ZIP, then `createFromZip`.
  - Environment variables move to the Vercel API.

### 19.2 Platform API v1 (legacy, `api.v0.dev/v1`, package `v0-sdk`)

- Projects (with env vars, instructions), chats (`create`, `init` from files, repo, registry or zip with no tokens used), versions (find, get, update/delete files, download zip or tarball, restore), fork, favorite, messages (find, get, send, resume, stop), deployments (create, find, logs, errors, delete), hooks, MCP servers, integrations, rate limits, plan, user, scopes, usage report, user activity.

## 20. Prompting best practices (official)

- **Mantra:** "Start simple. Plan your project. Provide context. Specify and make v0 clarify. Iterate."
- **Be specific:** cover functionality, design, and technical stack.
- **Break down complex apps:** for example a catalog, then a cart, then checkout. Use component-first and progressive enhancement.
- **Plan complex work first:** ask for a PRD or personas, then "Build the MVP based on the PRD". You can also enable the **Plan Mode** instruction.
- State UI/UX preferences (dark mode, mobile-first) and error, loading and empty states.
- **Full-stack:** UI first, then the data layer, then auth/CRUD, then enhancements, then optimization. Duplicate generations to add logic rather than mixing UI and logic in one prompt. Use popular libraries.
- Prompt templates (CRUD, Auth, Dashboard widget) are in the docs.
- Use **prompt queuing** (up to 10) for multi-step sequences.
- Screenshots: high resolution (at least 1024px), crop to focus, add behavior notes. Figma gives better results than screenshots. Name frames, use auto layout, use frame links for exact screens.
- **Snowflake:** inspect schemas before generating, and use LIMIT.
- **Credits:** specific prompts mean fewer iterations. Keep chats focused, because long history inflates input tokens.

## 21. Limitations and known complaints

- **Cost and credit burn** is the dominant complaint since the May 2025 token pricing. Users report $10–$30/day and "credits last 5–6 tasks" (Jun 2026). Failed generations are not refunded. ([superdesign review], community threads) [third-party]
- **Reliability regressions** after the Mar 2026 update: ignored prompts, bug loops, preview and connection errors. [third-party]
- Previews now run real builds, so they are **slower** than the old in-browser runtime (the FAQ acknowledges this).
- Best results come with Next.js. Other frameworks are second-class.
- Free tier: 7 messages/day, smaller upload limits. Figma import requires a paid plan.
- The preview sees **Development env vars only**. Sensitive vars are hidden.
- Design Mode: latest version only, not on mobile viewports, not on read-only chats.
- The Code editor is limited to 1 MB UTF-8 text files.
- Sandbox: 24h absolute cap, per-chat isolation.
- GitHub: v0 cannot push to base or main. Human reviews must happen on GitHub.
- MCP tools serve the agent only. Generated apps cannot call them.
- Figma rate limits are set by Figma.
- No offline mode.
- Vercel lock-in for the smoothest path. You can still export a ZIP or use GitHub to deploy elsewhere.
- Training: content of Free, Premium and Plus users may be used for training unless opted out in Vercel team data preferences. Business opts out by default. Enterprise is never used.

## 22. Security and compliance (summary)

- All LLM code is treated as untrusted: sandboxed execution, input validation, adversarial testing.
- Env-var hygiene: warnings about `NEXT_PUBLIC_`, and refactoring secrets into server code.
- Deployed functions are isolated, with an encrypted env vault.
- Automatic mass patching: **React2Shell** (Dec 2025, more than 800k deployments) and RSC CVEs CVE-2025-55184/55183.
- Hardening noted in the changelog: SSRF/DNS-rebinding protections, magic-link CSRF fixes.
- SOC 2 Type 2 (Vercel scope), GDPR. Enterprise adds SSO, audit logs, data isolation and session controls.
- Report vulnerabilities to security@vercel.com.
